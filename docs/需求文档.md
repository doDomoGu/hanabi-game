## 1. 产品概述

### 1.1 背景与目标

HANABI 是一款 **2～5 人合作** 卡牌游戏：玩家看不到自己的手牌，只能看到队友手牌，通过有限的「提示」协作，按颜色与数字顺序点亮烟花。

本项目目标是做一个 **可在手机浏览器游玩的在线版**：

- 支持多人同房对局（房间码加入）
- 服务端权威裁决规则，防止作弊
- 数据以 **JSON 文件** 持久化，无需数据库
- 界面以移动端竖屏为主，操作触控友好

### 1.2 非目标（首期不做）

- 账号体系 / OAuth 登录（首期可用昵称 + 房间码）
- 排行榜、社交、观战回放
- AI 机器人对战（可作为后续）
- 多色变体（彩虹牌等高级规则）：首期明确不做
- 出牌/回合倒计时：首期不做（无强制时间限制）
- 实时语音 / 文字聊天以外的复杂沟通工具
- 多语言界面（仅中文）

## 2. 游戏规则（产品必须实现）

规则以官方 Deluxe 基础规则为准；**不含彩虹牌等变体**。

### 2.1 牌组与令牌

| 元素 | 规则 |
|------|------|
| 颜色 | 红、黄、绿、蓝、白（共 5 色） |
| 每色牌数 | 1×3、2×2、3×2、4×2、5×1，合计 50 张 |
| 提示令牌（Clock） | 8 枚，开局全部可用 |
| 失误令牌（Fuse） | 3 次；第 3 次失误立即失败 |

### 2.2 人数与手牌

| 人数 | 每人手牌数 |
|------|------------|
| 2～3 人 | 5 张 |
| 4～5 人 | 4 张 |

**关键规则**：玩家 **不能查看自己手牌正面**；只能看到其他玩家的手牌。

### 2.3 回合行动（必须且仅能选一项）

1. **提示（Give Information）**
   - 消耗 1 枚可用提示令牌
   - 指定一名队友，选择一种信息类型：
     - **颜色**：指出该玩家手中 **所有** 该颜色的牌（必须完整指出）
     - **数字**：指出该玩家手中 **所有** 该数字的牌（必须完整指出）
   - 不允许「你有 0 张某某」（无可指向的牌时不能给该提示）
   - 提示令牌为 0 时不可执行

2. **弃牌（Discard）**
   - 弃掉自己一张手牌到弃牌区（所有人可见）
   - 若提示令牌未满，恢复 1 枚
   - 从牌库抽 1 张补到手牌（牌库空则不抽）
   - 提示令牌已满（8）时不可弃牌

3. **出牌（Play）**
   - 打出自己一张手牌到对应颜色烟花区
   - **成功**：该色下一张必须正好是「当前最高 + 1」（该色尚无牌时只能打 1）
   - **失败**：牌进入弃牌区，消耗 1 次失误；失误达 3 立即失败
   - 成功打出 **5** 完成该色烟花：若提示令牌未满，额外恢复 1 枚提示
   - 出牌后从牌库抽 1 张（牌库空则不抽）

### 2.4 终局与计分

游戏在以下情况结束：

1. **失败**：第 3 次失误 → 立即结束，失败
2. **满分胜利**：五色烟花全部完成（各到 5）→ 立即结束，得分 25
3. **牌库抽空**：有人抽到最后一张后，**每位玩家再行动一轮**（含抽到最后一张的玩家），此轮不再抽牌；结束后按得分结算

**得分**：五色烟花各自已完成的最高数字之和（满分 25）。

| 分数 | 评价（展示用） |
|------|----------------|
| ≤5 | Horrible |
| 6–10 | Mediocre |
| 11–15 | Honorable |
| 16–20 | Excellent |
| 21–24 | Amazing |
| 25 | Legendary |

## 3. 用户与房间流程

### 3.1 角色

- **房主**：创建房间、可选开始游戏、可踢人（首期可选）
- **玩家**：输入昵称加入房间，参与对局
- 首期不做独立用户账号；以 `playerId`（本地生成 UUID）+ 昵称标识

### 3.2 主流程

```
进入首页
  → 创建房间 / 输入房间码加入
  → 大厅：等待玩家、显示准备状态
  → 房主开始游戏（人数 2～5）
  → 对局中：轮流出牌 / 提示 / 弃牌
  → 结算页：得分、评价、再来一局 / 返回大厅
```

### 3.3 房间状态机

```
waiting  →  playing  →  finished
              ↓
           (可中途解散 → finished / abandoned)
```

## 4. 功能需求

### 4.1 大厅与房间

| ID | 需求 | 优先级 |
|----|------|--------|
| R1 | 创建房间，生成短房间码（如 6 位） | P0 |
| R2 | 通过房间码加入；昵称必填 | P0 |
| R3 | 大厅展示玩家列表、准备状态、人数限制 2～5 | P0 |
| R4 | 房主在人数合法且（可选）全员准备后开始游戏 | P0 |
| R5 | 断线重连：同一 playerId 可回到原房间/对局视角 | P0 |
| R6 | 房间超时或空房间清理（文件侧可定时/懒清理） | P1 |

### 4.2 对局核心

| ID | 需求 | 优先级 |
|----|------|--------|
| G1 | 开局洗牌、发牌、初始化令牌与烟花区 | P0 |
| G2 | 视角隔离：自己手牌只显示牌背 + 已知提示标记；他人手牌正面可见 | P0 |
| G3 | 执行提示 / 弃牌 / 出牌，服务端校验合法性 | P0 |
| G4 | 提示必须完整标记所有匹配牌；UI 高亮被指出的牌位 | P0 |
| G5 | 展示：牌库剩余、弃牌区、提示/失误令牌、五色烟花进度 | P0 |
| G6 | 当前行动玩家高亮；非本人回合不可操作 | P0 |
| G7 | 终局三种情况正确判定；展示得分与评价 | P0 |
| G8 | 操作历史（简短日志：谁提示了什么 / 谁打了什么） | P1 |
| G9 | 再来一局（同房间重新开局） | P1 |

### 4.3 移动端界面

| ID | 需求 | 优先级 |
|----|------|--------|
| U1 | 竖屏优先布局；关键按钮触控区域足够大 | P0 |
| U2 | 他人手牌横向/环绕展示，当前玩家手牌固定底部 | P0 |
| U3 | 出牌/弃牌：先选牌再确认，防误触 | P0 |
| U4 | 提示流程：选目标 → 选颜色或数字 → 预览将高亮的牌 → 确认 | P0 |
| U5 | 适配常见手机宽度（约 360～430px）；桌面居中窄栏亦可 | P0 |

### 4.4 实时同步

| ID | 需求 | 优先级 |
|----|------|--------|
| S1 | 对局状态变更后，房间内所有客户端及时更新 | P0 |
| S2 | 使用 WebSocket 推送房间/对局状态变更（首期必做） | P0 |
| S3 | 心跳与断线检测；超时标记离线；首期无出牌倒计时，断线后等待重连（不自动代打） | P1 |

## 5. 技术架构需求

### 5.1 总体

```
[Vue SPA / 移动端浏览器]
        │  HTTP + WebSocket
        ▼
[Node.js API 服务]
        │  读写
        ▼
[本地 JSON 文件存储]
  data/rooms/{roomCode}.json
  data/games/{gameId}.json   （或合并进房间文件）
```

### 5.2 前端（Vue）

- Vue 3 + Vite
- 路由：首页 / 房间大厅 / 对局 / 结算
- 状态：Pinia 或等价方案
- 样式：移动优先；不依赖原生 App
- 文案：仅中文
- 本地持久化：`localStorage` 保存 `playerId`、昵称、最近房间码

### 5.3 后端（Node.js）

- 提供 REST（创建/加入房间、查询状态）+ WebSocket（推送状态）
- **游戏规则引擎在服务端**：洗牌、发牌、行动校验、终局判定
- 客户端不可信任（不能让客户端上报「我打出红 3 成功」这类结果）

### 5.4 文件存储

- 每个房间一个 JSON 文件（或房间 + 对局拆分）
- 写入需保证原子性（先写临时文件再 rename）或简单文件锁，避免并发损坏
- 不引入 MySQL / Redis（首期明确约束）
- 可配置数据目录路径

### 5.5 建议的核心数据结构（示意）

```json
{
  "roomCode": "AB12CD",
  "status": "playing",
  "hostPlayerId": "...",
  "players": [
    { "id": "...", "name": "Alice", "ready": true, "connected": true }
  ],
  "game": {
    "deck": [],
    "discard": [],
    "fireworks": { "red": 0, "yellow": 0, "green": 0, "blue": 0, "white": 0 },
    "hints": 8,
    "fuses": 3,
    "turnIndex": 0,
    "hands": {
      "playerId": [
        { "id": "c1", "color": "red", "value": 1, "hints": { "color": null, "value": null } }
      ]
    },
    "lastActions": [],
    "phase": "normal | finalRound",
    "finalTurnsLeft": null,
    "score": null,
    "result": null
  }
}
```

> 发给客户端时：对「本人」手牌剥离 `color/value`，只保留 `id` 与已知 `hints`；对他人完整可见。

## 6. 界面信息架构（移动端）

### 6.1 首页

- 标题 / 简短说明
- 「创建房间」「加入房间」
- 昵称输入

### 6.2 大厅

- 房间码（可复制）
- 玩家列表 + 准备
- 开始按钮（房主）
- 简单规则入口（折叠）

### 6.3 对局页（核心）

自上而下建议：

1. 顶栏：提示令牌、失误、牌库剩余、当前回合
2. 烟花区：五色进度
3. 其他玩家手牌（可见正面 + 提示高亮）
4. 弃牌区入口（抽屉/弹层）
5. 底部：自己的手牌（牌背 + 已知颜色/数字标记）+ 行动按钮

### 6.4 结算页

- 得分与评价文案
- 五色最终高度
- 「再来一局」「离开房间」

## 7. 非功能需求

| 类别 | 要求 |
|------|------|
| 性能 | 单机文件存储下，同时活跃房间建议支持数十量级；单房间推送延迟体感 &lt; 1s |
| 可用性 | 误操作需二次确认（出牌/弃牌）；网络抖动有重试提示 |
| 安全 | 房间码不可枚举过易；服务端校验座位与回合；不向前端泄露本人牌面 |
| 兼容 | 现代移动浏览器（iOS Safari / Android Chrome 近两年版本） |
| 可维护 | 规则逻辑独立模块，便于单测 |

## 8. 里程碑建议

### Phase 1 — MVP（可玩）

- 房间创建/加入、开始对局
- 完整规则引擎（基础五色，无变体）
- 视角隔离 + 三种行动
- 文件持久化 + WebSocket 同步
- 移动端中文对局 UI

### Phase 2 — 体验完善

- 操作历史、弃牌区浏览、再来一局
- 断线重连体验、离线提示
- 规则说明页、结算动画

### Phase 3 — 扩展（可选）

- 彩虹牌变体开关
- 回合出牌倒计时（若后续需要）
- 观战、回放
- 简单 AI 补位
- 账号与历史战绩

## 9. 验收标准（MVP）

1. 2～5 人可组局并完成至少一局完整对局（含成功提示、弃牌、出牌成功/失败）。
2. 任意玩家刷新页面后，仍能以正确视角回到同一对局。
3. 非法行动（非本人回合、提示令牌不足、不完整提示等）被服务端拒绝。
4. 三种终局与计分符合第 2 章规则。
5. 在手机竖屏下可完成完整操作流程，无需横屏。

## 10. 已确认决策

| 事项 | 结论 |
|------|------|
| 实时同步 | 首期使用 **WebSocket** |
| 界面语言 | **仅中文** |
| 彩虹牌变体 | **首期不做** |
| 出牌时间限制 | **首期不做**（无回合倒计时；玩家可慢慢想） |
| 断线策略 | **只等重连**：不代打、不跳过回合 |

### 说明：断线 ≠ 出牌限时

此前「断线策略」指的是：**某人网络断开后，房间怎么处理**，不是出牌有没有倒计时。

已确认约定：

- 无出牌/回合时间限制
- 玩家断线后标记为离线，**对局等待其重连**
- **不代打、不自动跳过回合**
- 同一 `playerId` 刷新/重进可恢复视角与操作权

若后续需要「限时出牌」或「断线超时自动跳过」，再单独立项。

### 仍可后续确认

- 部署方式：单机 Node + 本地磁盘 / 是否 Docker
